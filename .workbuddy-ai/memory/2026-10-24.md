## 修复 GRID 面板「有时候出现黑色虚线框」

- 现象：JSON 数据解析页右侧 GRID 偶尔整块外圈出现一圈黑色 1px 点线框。
- 定位：截图按 2x DPI 解码后逐像素扫描，虚线框实测 x 1235~2532、y 197~1491，四角是直角；而 `GridPanel` Border 是 `CornerRadius=8` 圆角，所以不是 Border 边框。该范围恰好等于 `GridScrollViewer` 的边界（工具栏下沿 → 面板左右边 → 面板底边），且点线为纯黑、1px、1on/1off —— 即 WPF 默认 `SystemParameters.FocusVisualStyleKey`（Rectangle StrokeDashArray="1 1"）。
- 原因：WPF 的 `ScrollViewer` 是可聚焦控件，`OnMouseLeftButtonDown` 内部直接 `Focus()`，点 GRID 空白/展开箭头就会把键盘焦点交给它；`FocusVisualStyle` 只在「键盘线索可见」时绘制，所以鼠标点完不显示、随后一按键才冒出来 → 表现为「有时候」。
- 修复：`Themes/CommonStyles.xaml` 增加隐式 `<Style TargetType="ScrollViewer">` 设 `FocusVisualStyle={x:Null}`（并给 `PageScrollViewerStyle` 补同样 setter，因为它走显式 Style 不继承隐式样式）；`JsonToolPage.xaml` 的 `GridScrollViewer` 再加一层本地 `FocusVisualStyle="{x:Null}"`。`dotnet build` 通过（0 警告 0 错误）。
- 备注：同类问题适用于全项目 11 个页面里的所有 ScrollViewer。（~~Page 的 Focusable=true 不受影响~~ —— **此判断后被证伪，见下一节**）

### 扩展到全项目 10 个页面（用户反馈「其他页面也有」）

- 关键结论：**XAML 里 `<Setter Property="FocusVisualStyle" Value="{x:Null}"/>` 并不可靠**。用 `DependencyPropertyHelper.GetValueSource` 实测，值来源分别是 `DefaultStyle`（主题样式 setter）和 `TemplateTrigger`（控件模板里的触发器）；而 **模板触发器优先级高于样式 Setter**，所以 CheckBox 这类用系统默认模板的控件，Setter 会被压过。唯一稳定的是**本地值**（元素属性或代码赋值），其次是 **Style 触发器**。
- 另一个坑：页面里各自定义的 `x:Key` 样式**不会继承**全局隐式样式，必须逐个补；`Style="{x:Null}"` 还会主动屏蔽隐式样式。
- 试过但放弃的方案：`EventManager.RegisterClassHandler(typeof(Control), FrameworkElement.LoadedEvent, ...)` 在 Loaded 时统一写本地 null —— 实测只命中 52~269 次（远少于控件数），且 Loaded 时刻样式往往还没应用（读到 null，加 `!= null` 判断就完全不生效）。已删除该文件，不留死代码。
- 最终做法：
  1. `Themes/CommonStyles.xaml` 补 15 个隐式样式（Button/ToggleButton/RadioButton/CheckBox/TextBox/PasswordBox/ComboBox/ComboBoxItem/ListBox/ListBoxItem/TreeViewItem/MenuItem/ScrollViewer/GridSplitter/RepeatButton）设 `FocusVisualStyle={x:Null}`；
  2. 脚本批量给 17 个 XAML 里已有的 `x:Key` 样式注入同一行（共 52 处，含 Themes 与 Views）；
  3. 剩 5 个特例用元素级本地属性：JsonToolPage 的两个 `Chk*CaseSensitive`、InvoicePrintPage 的 `ChkCutLine`（默认模板 + 模板触发器），以及 JsonDiffPage 里显式 `Style="{x:Null}"` 的 `DiffNavigation`/`DiffDetails`。
- 验证工程：`artifacts/focus-visual-qa/`（照 `artifacts/*-qa` 惯例新建）。反射注入样例 JSON → 强制 RebuildGrid → 遍历视觉树统计「可聚焦且 FocusVisualStyle 非空」的控件。10 个页面全部 0，PASS。主程序 `dotnet build` 0 警告 0 错误。
- 约定（新页面注意）：自定义 `x:Key` 样式若 TargetType 是可聚焦控件（Button/CheckBox/TextBox/DataGrid…），必须自带 `<Setter Property="FocusVisualStyle" Value="{x:Null}"/>`，否则焦点虚线框会回来。

### 第三轮：真正的主因是 `Page` 本身（用户截图「每个页面右侧整体一圈大框」）

- 现象修正：之前修的 ScrollViewer/CheckBox 只是「局部框」；用户实际看到的「整块右侧一圈」另有来源。
- 用 QA 工程打印 `page.FocusVisualStyle` 才发现：**11 个页面对象的 `FocusVisualStyle` 全都是非 null**，`ValueSource=Default`、`Style=null`、`Local=Unset`。
- 两个新结论（.NET 10 / net10.0-windows 特有，很重要）：
  1. **`FrameworkElement.FocusVisualStyle` 的元数据默认值不再是 null**，而是一个真实 Style（`SystemParameters.FocusVisualStyle` 这个 API 在 .NET 10 里已被删除，编译直接报 CS0117）。所以任何**可聚焦的非 Control**（Page）都会画出系统焦点框。
  2. **隐式样式对 `Page` 不生效**（`<Style TargetType="Page">` 加了以后 `page.Style` 仍是 null），只有元素上的**本地值**能压住 Default。
- 成因链：`MainWindow.MainFrame`（`Frame`，Control，隐式样式可覆盖）承载所有页面；每个页面在 `Page_Loaded` 里 `Focusable = true; Focus();`（为了 Ctrl+F / Esc 的 Page 级 InputBindings），于是键盘焦点落在 Page 上 → 整块右侧内容区被框住。每个页面都这么写，所以「每页都有」。
- 修复：
  - 11 个 `Views/*.xaml` 的 `<Page>` 根节点各加 `FocusVisualStyle="{x:Null}"`（脚本批量插入，本地值）；
  - `MainWindow.xaml` 的 `MainFrame` 加 `FocusVisualStyle="{x:Null}"`；
  - `Themes/CommonStyles.xaml` 补隐式 `<Style TargetType="Frame">`（Frame 是 Control，隐式样式有效）。
- QA 工程同步加强：改成用真实的 `Frame` 承载页面（和 MainWindow 一致），并把根节点本身也纳入扫描 + 单独断言 `page.FocusVisualStyle == null`，否则会漏掉这一整类问题。
- 结果：11 个页面 + Frame + 全部可聚焦控件，FocusVisualStyle 全为 null；`dotnet build` 0 警告 0 错误。
