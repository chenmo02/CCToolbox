## 1. 程序定位

**CC 实施工具箱（程序集名 `CCToolbox`）** 是一个 Windows 桌面单体应用，把实施现场高频的几类数据处理动作集中到一个窗口里：

- 表格文件（Excel / CSV / DBF）→ 建表与 INSERT 脚本
- 已有 INSERT 语句 → 反推字段并生成 CREATE TABLE
- 目标表结构 + 待导入数据 → 逐行逐字段的格式与约束校验
- 两份 CSV / 两份 JSON → 结构化差异对比
- PDF / 图片发票 → 排版、预览与打印
- 附带在线画板、随手记、系统参数配置

运行形态是**纯本地单机程序**：除「在线绘图工具」通过 WebView2 加载 excalidraw.com 需要联网外，其余功能全部在本机内存中完成，不连接任何数据库、不上传文件。程序**不具备数据库直连能力**，SQL 只负责生成，执行由用户自行在数据库客户端完成。

| 项目 | 取值 |
|------|------|
| 目标框架 | `net10.0-windows10.0.19041.0` |
| UI 框架 | WPF（XAML + code-behind，无 MVVM 框架） |
| 输出类型 | `WinExe`，单文件自包含发布（win-x64） |
| 程序集名 | `CCToolbox` |
| 根命名空间 | `WpfApp1`（历史命名，与产品名不一致） |
| 源码规模 | 约 26,240 行（`.cs` + `.xaml`，不含 bin/obj/artifacts） |
| 最低系统 | Windows 10 19041 及以上 |

## 4. 启动与导航

### 4.1 启动链路

1. `App.xaml` 通过 `StartupUri="MainWindow.xaml"` 启动主窗口，并合并 8 个资源字典：`LightTheme`、`ScrollBarStyles`、`ToastStyles`、`ButtonStyles`、`DataGridStyles`、`InputStyles`、`CardStyles`、`CommonStyles`。
2. `App.OnStartup` 注册三层异常兜底：
   - `DispatcherUnhandledException`：UI 线程异常，弹窗后 `Handled = true`，避免闪退；
   - `AppDomain.UnhandledException`：非 UI 线程异常；
   - `TaskScheduler.UnobservedTaskException`：未观察的 Task 异常，标记已观察。
3. `MainWindow` 构造时创建**唯一的** `HomePage` 实例并导航到它。
4. `GlobalUsings.cs` 把 `MessageBox` 全局别名到 `WpfApp1.Services.AppMessageBox`，因此全项目 `MessageBox.Show(...)` 实际调用的是自定义圆角对话框。

### 4.2 导航结构

左侧固定 220px 导航栏，10 个 `RadioButton`（`NavButtonStyle`）分四组，右侧 `Frame` 承载页面：

| 分组 | 导航项 | 目标页面 | 实例策略 |
|------|--------|----------|----------|
| 数据工具 | 首页数据概览 | `HomePage` | 复用同一实例 |
| 数据工具 | 临时数据建表 | `DataImportPage` | 每次新建 |
| 数据工具 | CSV文件预览 | `CsvViewerPage` | 每次新建 |
| 数据工具 | 快速建数据表 | `QuickTablePage` | 每次新建 |
| 数据工具 | 数据验证排查 | `DataValidationPage` | 每次新建 |
| 开发工具 | JSON数据解析 | `JsonToolPage` | 每次新建 |
| 开发工具 | JSON内容比对 | `JsonDiffPage` | 每次新建 |
| 开发工具 | 在线绘图工具 | `DrawBoardPage` | 每次新建 |
| 办公工具 | 发票打印操作 | `InvoicePrintPage` | 每次新建 |
| 系统 | 系统参数配置 | `SettingsPage` | 每次新建（`Click` 事件而非 `Checked`） |

**隐藏入口**：CSV 对比页不在导航栏中，只能从「系统参数配置 → 实用小工具 → CSV 对比」进入；`MainWindow.NavigateToCsvCompare()` 会同时把 `NavSettings` 置为选中，因此界面停留在设置项上但内容区是 CSV 对比页。

**随手记**：右下角悬浮球，按下后拖动可改变 `Margin`（带 3px 阈值区分点击与拖拽），点击打开 `QuickNotesWindow`（单例复用）。

### 4.3 页面生命周期约定

- 页面均为 `Page`，通过 `Frame.Navigate` 加载；离开时 `Page.Unloaded` 负责退订静态事件（如 `ImportSettingsService.SettingsSaved`）与停止滚动动画，避免内存泄漏。
- 设置变更通过静态事件 `ImportSettingsService.SettingsSaved` 广播，`DataImportPage` 订阅后刷新 UI 默认值。

## 5. 主要业务流程

### 5.1 表格文件 → 建表 / INSERT 脚本（临时数据建表）

```
选择/拖入文件 → 识别扩展名 → 解析为 DataTable → DataGrid 预览与编辑
      → 选择数据库/表名/选项 → GenerateFullSql → 预览（超长截断）
      → 复制 / 保存 .sql / 导出 CSV / 导出 JSON
```

关键行为：

- 支持 `.xlsx`（EPPlus）、`.xls`（ExcelDataReader）、`.csv`（CsvHelper）、`.dbf`（手写二进制解析）。`.bdf` 只在 CSV 预览页与解析服务中支持，本页文件对话框未列出。
- Excel 先读工作表列表供切换；DBF 提供 8 种编码下拉（UTF-8 / GB2312 / GBK / GB18030 / Big5 / UTF-16 / ASCII / Windows-1252），默认 UTF-8，切换后重新加载。
- 预览表可编辑，生成 SQL 前调用 `CommitEdit` 提交未落盘的单元格。
- 超过 100,000 行时弹确认框；SQL 超过 5,000 行时编辑框只显示前 1,000 行，但复制/保存仍是完整内容（状态栏会提示）。
- 快捷键：`Ctrl+O` 打开、`Ctrl+S` 保存 SQL、`F5` 生成、`Ctrl+R` 重新加载。
- 生成过程有遮罩动画（spinner → 完成 → 淡出），期间禁用编辑与重复加载。

### 5.2 INSERT 语句 → CREATE TABLE（快速建数据表）

```
粘贴 INSERT → 解析字段与数据行 → 推断字段类型/长度
   → 人工调整（类型、长度、精度、可空、批量应用、大小写、表名前缀）
   → 生成四类数据库的 CREATE TABLE → 复制 / 导出
```

- 表名前缀从 `settings.json` 的 `QuickTablePrefix` 读取（默认 `TJK_`），可保存回配置。
- 「引用标识符」开关控制是否给表名/字段名加引号（MySQL 反引号、SQL Server 方括号、PG/Oracle 双引号）。
- 类型只有 6 个归一选项：`varchar`、`text`、`bigint`、`numeric`、`timestamp`、`boolean`，再按目标数据库映射为具体类型。

### 5.3 数据验证排查（四步向导）

```
① 结构输入            ② 数据输入            ③ 字段映射              ④ 校验与报告
DDL 或结构 Excel  →  INSERT 或数据 Excel  →  自动匹配 + 人工确认  →  逐行校验 + Excel 报告
```

各步要点：

- **步骤 1**：`DdlParser` 解析 DDL，并用关键词打分自动识别 SQL Server / PostgreSQL；识别结果与下拉选项不一致时弹窗询问是否切换。也可导入结构 Excel（列名支持 `column_name/字段名/列名` 等别名）。页面同时给出对应数据库的 `information_schema` 查询语句供复制。
- **步骤 2**：粘贴 INSERT（超过 5,000 字符时先显示遮罩再赋值，避免 UI 卡顿）或导入数据 Excel。文本一旦改动即把旧解析结果标记为失效，防止用过期数据继续。
- **步骤 3**：`FieldMatcherService.AutoMap` 生成映射，按 UUID 字段优先排序展示；支持三种映射方式（源字段 / 固定值 / 忽略）、按字段名搜索、逐条确认、`确认全部`、`忽略全部 UUID`、跳到下一个未确认项。UUID 字段**永不自动确认**。
- **步骤 4**：异步校验（可取消），实时进度；完成后展示摘要卡片、错误类型环形图、按类型/关键字筛选、分页明细、复制单元格/整行、右键把实际值加入忽略列表、导出三 Sheet 的 Excel 报告。

### 5.4 CSV 对比

```
加载文件 A / B → 选择模式（行号 / 复合主键）→ 对比
   → 汇总列表（按差异类型分组、分页）→ 选中查看字段级明细
   → 筛选 / 复制报告 / 导出 CSV
```

- 字段差异（新增列 / 缺失列）单独用横幅展示，不混入行级列表。
- 主键模式会先检查重复主键：一旦某侧存在重复键，停止正常对比，只展示重复键问题，提示先修数据。
- 结果分组排序：字段缺失 → 字段新增 → 主键重复 → 行缺失 → 行新增 → 单元格差异。
- 页面状态（两份表、上次结果、模式、主键、筛选、分页）保存在 `CsvCompareStateService` 的**进程内静态对象**，切页再回来可恢复；退出程序即丢失。

### 5.5 JSON 处理与对比

**JSON 数据解析**（双栏）：

```
左：纯文本编辑器（语法高亮、行号、搜索）  右：嵌套 GRID（可折叠、表格化、可编辑回写）
```

- 输入合法 JSON 后自动美化并重建右侧结构；对象数组渲染为多列表格，简单数组渲染为单列表格，嵌套对象/数组可继续展开。
- GRID 支持编辑模式：单元格改值后按 JSON 路径回写到左侧文本，并做类型推断（数字/布尔/字符串/嵌套 JSON）。
- 双搜索：左侧文本搜索（高亮 + 上下定位）与右侧 GRID 搜索（自动展开命中节点 + 高亮 + 路径联动）；点击 GRID 值可反向定位到左侧对应 token。
- 支持全屏 GRID、全部展开/折叠、导入 JSON、导出 JSON / CSV。

**JSON 内容比对**：

- 递归比较对象键集合、数组下标、基本类型值，差异分四类：新增、删除、修改、类型变化。
- 通过 `Utf8JsonReader` 的 `TokenStartIndex` 把 JSON 路径映射到源码行号，避免重复键或转义字符导致的文本搜索错位。
- 差异列表与明细表联动，点击定位两侧行号并高亮行标记；支持按类型筛选、只看差异、复制/导出文本报告。

### 5.6 发票打印

```
导入文件/文件夹（PDF、OFD、JPG、PNG、BMP、TIF）→ 左侧列表
   → 中间预览（翻页、旋转、缩放）→ 右侧打印设置（布局、纸张、边距、套打偏移、裁剪线、模板）
   → 打印机预览 / 开始打印（进度与队列状态回传）
```

- 文件按「路径 + 大小 + 修改时间」计算哈希去重。
- PDF 用 WinRT `Windows.Data.Pdf` 渲染；图片直接 `BitmapImage` 加载；OFD 只登记不渲染（预览为空）。
- 排版：A4 或发票专用纸（241×140mm），每页 1/2/4 张，4mm 间距，等比缩放居中，可画虚线裁剪线与剪刀标记。
- 打印在独立 STA 线程执行（`RunPrintWorkerAsync`），避免打印队列与 WPF 视觉对象跨线程问题；提交后轮询队列最多 60 秒，把 `PrintJobStatus` 翻译成「缺纸 / 卡纸 / 离线 / 已暂停 / 完成」等中文状态。
- 打印历史保留最近 500 条。

### 6.2 文件解析

`FileParserService` 按扩展名分派：

- `.xlsx`：EPPlus，`DimensionByValue` 取实际数据范围，首行作表头，所有单元格按 `Text` 取字符串。
- `.xls`：ExcelDataReader，`UseHeaderRow = true`，`TransformValue` 统一转字符串后重建 `DataTable`。
- `.csv`：转交 `DelimitedTextFileService`，保留字段原始格式（不 Trim）。
- `.dbf` / `.bdf`：手写 DBF 头解析（字段数 = `(headerLength-33)/32`），跳过删除标记 `0x2A` 的行，按指定编码逐字段解码。

列名去重统一走 `GetUniqueColumnName`：空名补 `ColumnN`，重名追加 `_2`、`_3`。

编码识别顺序：BOM（UTF-8 / UTF-16 LE / BE）→ 严格 UTF-8 解码尝试 → 失败回退 GBK。分隔符按首行 `,` `\t` `;` `|` 出现次数取最多者。

### 6.3 SQL 生成（`SqlGeneratorService`）

**标识符处理**

- 列名清洗：保留字母、数字、下划线、非 ASCII 字符，其余替换为 `_`，去首尾 `_`，转小写，数字开头补 `c_`，重名追加 `_2`。
- 表名清洗：同样规则，数字开头补 `t_`；SQL Server 临时表自动加 `#`；PG/MySQL/Oracle 临时表不加前缀。
- 引用符：MySQL `` ` ``、SQL Server `[]`（`#` 临时表不加）、PG/Oracle 不加。

**DROP 语句差异**

| 数据库 | 生成形式 |
|--------|----------|
| PostgreSQL / MySQL | `DROP TABLE IF EXISTS x;` |
| SQL Server | 临时表：`IF OBJECT_ID('tempdb..#x') IS NOT NULL DROP TABLE #x;`；普通表：`IF OBJECT_ID('x','U') IS NOT NULL DROP TABLE [x];` |
| Oracle | `BEGIN EXECUTE IMMEDIATE 'DROP TABLE x'; EXCEPTION WHEN OTHERS THEN IF SQLCODE != -942 THEN RAISE; END IF; END; /` |

**CREATE 语句差异**

- PG / MySQL：`CREATE TEMPORARY TABLE`
- Oracle：`CREATE GLOBAL TEMPORARY TABLE ... ON COMMIT PRESERVE ROWS`
- SQL Server：`CREATE TABLE`（临时表靠 `#` 前缀）
- 所有字段一律带 `NULL`。

**INSERT 语句差异**

- 关闭批量：逐行 `INSERT INTO ... VALUES (...);`
- 开启批量：非 Oracle 生成多值 `INSERT INTO ... VALUES (...),(...);`；Oracle 生成 `INSERT ALL ... SELECT 1 FROM DUAL;`
- SQL Server 批量上限强制 1000 行（SQL Server 单条 VALUES 的硬限制）。

**类型与取值**

- 临时建表**所有列都按字符串处理**（源码注释：保持导入值原样，不自动改写布尔/数值）。因此日期、数字在 SQL 里都是带引号的字符串，由目标库隐式转换。
- `限制文本长度` 开启时统一 `VARCHAR(1000)`；关闭时按实际最大长度（上限 4000），超过 4000 用 `TEXT` / `LONGTEXT` / `CLOB` / `NVARCHAR(MAX)`。
- 空值与空字符串统一输出 `NULL`，单引号转义为 `''`。
- 末尾附带 `SELECT COUNT(*)` 校验语句和注释掉的预览查询（PG/MySQL `LIMIT 10`，Oracle `FETCH FIRST 10 ROWS ONLY`）。

> 注意：`InferColumnKind`（按样本推断布尔/整数/小数/日期）虽然实现了，但没有任何调用点，属于死代码。当前行为是「全部字符串」。

### 6.4 DDL 与 INSERT 解析

**`DdlParser`**

- 先剥离 `--` 行注释与 `/* */` 块注释，再取最外层括号内容，按顶层逗号切分。
- 跳过表级约束（`PRIMARY` / `UNIQUE` / `INDEX` / `CONSTRAINT` / `KEY` / `CHECK`），但会记录表级主键列，并把它们标记为非空。
- 字段定义中剥离 `DEFAULT`、`IDENTITY`、`COLLATE`、`GENERATED`；字段级 `PRIMARY KEY` 同样视为非空。
- 多词类型归一：`character varying` → `varchar`、`double precision` → `float`、`timestamp without time zone` → `timestamp` 等。
- 数据库探测用加权打分：PG 侧 `uuid`/`serial`/`jsonb`/`timestamptz`/`::` 等，SQL Server 侧 `uniqueidentifier`/`nvarchar`/`datetime2`/`IDENTITY(`/`[]` 等，分高者胜，平局返回「无法判断」。

**`InsertStatementParser`**

- 手写字符扫描器，识别单引号字符串、双引号/方括号/反引号标识符、`--` 与 `/* */` 注释，因此字符串里的逗号、括号、关键字不会误判。
- 支持多条 INSERT、单条多行 VALUES、`N'...'` Unicode 字符串、`NULL`。
- 多条 INSERT 字段顺序不一致时，按第一条的字段顺序重排并返回警告；字段集合不一致直接报错。
- 字段数必须与值个数一致，否则抛出明确中文异常。

### 6.5 字段自动匹配（`FieldMatcherService`）

五轮「先到先得」，已被占用的源字段不会重复匹配：

| 轮次 | 方式 | 置信度 | 规则 |
|------|------|--------|------|
| 1 | 精确 | 100 | 字段名完全一致（忽略大小写） |
| 2 | 标准化 | 95 | 去掉 `-` `_` 空格并转小写后一致 |
| 3 | 前缀剥离 | 90 | 去掉 `zjb_`/`tmp_`/`mid_`/`src_` 前缀与 `_text`/`_str`/`_value` 后缀后一致，且语义族兼容 |
| 4 | 语义优先 | 84–92 | 同基名 + 语义族匹配（如 `*_mc` 配名称、`*_dm` 配代码、`*_icd10` 配外部编码） |
| 5 | 包含（待确认） | 55–68 | 字段名互相包含，标记 `NeedsConfirmation` |

语义族由后缀识别：`icd10mc/icd9mc/icdmc/dmmc` → 名称，`icd10/icd9/icd` → 外部编码，`uuid/guid/code/dm/id` → 标识，`name/mc/xm` → 名称，`desc/ms/jc/yy/xx` → 说明。这套后缀明显带有医疗/病案数据背景（`zjb_`、`dmmc`、`icd10`），是项目现场的约定而非通用规则。

UUID 目标字段：即使匹配到来源也**不自动确认**，必须人工核对；`id`、`baid`、`*uuid`、`*guid` 这类明显由系统生成的字段允许默认忽略，不计入「必填未映射」。

### 6.6 校验引擎（`ValidationEngine`）

执行顺序固定：**先判空 → 非空约束 → 可空空值放行 → 按归一类型分派**。

| 归一类型 | 规则 |
|----------|------|
| String | 按原始长度（含前后空格）校验 `MaxLength`；SQL Server 的 `varchar/char` 含非 ASCII 时额外给「字节可能超长」警告 |
| Integer | 允许 `3.0` 这类整数值小数，拒绝 `3.14`/`1,000`/`abc`；再按 `tinyint/smallint/int` 做范围校验 |
| Long | 同上格式检查，范围交给 `long` |
| Decimal | 按 InvariantCulture 解析；有 precision/scale 时分别校验整数位与小数位 |
| Date | 仅接受 `yyyy-MM-dd` / `yyyy/MM/dd` / `yyyyMMdd`（精确匹配，不用宽松解析） |
| DateTime | 一组固定格式，含毫秒/微秒/纳秒与仅日期回退；`datetimeoffset`/`timestamptz` 必须带时区偏移 |
| Time | `HH:mm[:ss[.fff...]]`；`timetz`/`time with time zone` 必须带偏移 |
| Boolean | 白名单：真 `1/true/yes/y/是/t`，假 `0/false/no/n/否/f` |
| Guid | `Guid.TryParse` |
| Json | 仅校验语法，不校验 Schema |
| Unknown | 只做非空校验，并给一条「未识别类型」警告 |

其他机制：

- 主键列用于结果定位（`主键=值`），错误统计按主键去重；无主键时按行号去重。
- 必填但完全未映射的字段，会对**每一行**补一条「必填未映射」错误。
- 问题明细上限 **10,000 条**，达到后截断并标记 `WasTruncated`。
- 三个「跳过格式错误」开关分别只影响整数类、GUID、日期时间类（不含纯 `Date`）。
- 支持「忽略指定实际值」集合，命中后该单元格直接跳过。

### 6.7 CSV 对比（`CsvCompareService`）

- 先产出字段级差异（`ColumnAdded` / `ColumnRemoved`），再按模式比较数据。
- **行号模式**：第 N 行对第 N 行，行数不等时多出的行标为新增/缺失。
- **主键模式**：用 `\u001f` 连接各主键值生成复合键；重复键会生成 `DuplicateKey` 差异并写入校验错误，页面据此停止正常对比。
- 行预览只取前 4 列，单值超过 28 字符截断为 `前25字符...`。
- 差异分组排序：字段缺失(1) → 字段新增(2) → 主键重复(3) → 行缺失(4) → 行新增(5) → 单元格差异(6)。

### 6.8 JSON 服务

`JsonToolService`：美化/压缩（`JsonSerializer` + `UnsafeRelaxedJsonEscaping` 保留中文）、校验（返回行号与节点数/最大深度）、JSON → `DataTable`、`DataTable` → JSON、JSON → CSV。其中 `ParseToTree`、`ExtractByPath` 无调用点，属于备用 API。

`JsonGridParser`：构建 `JsonGridNode` 树，同时为数组节点生成表格数据：

- 对象数组 → 多列表格（扫描全部行收集列名，最多 80 列；最多 1,000 行）；
- 简单数组 → 单列表格；
- 嵌套对象/数组 → `NestedChildren`，在单元格内继续折叠展开；
- 每个节点/单元格记录 JSON 路径，路径片段做 `~0` / `~1` 转义，供编辑回写与搜索定位。

### 6.9 发票打印（`InvoicePrintService`）

- `RunPrintWorkerAsync`：新建 STA 线程 + Dispatcher，把打印工作整体搬离 UI 线程。
- `PreparePrintJob`：解析 `\\server\queue` 形式打印机名，`MergeAndValidatePrintTicket` 合并纸张/方向/单面设置，从 `PageImageableArea` 取可打印区域。
- `BuildPrintPages`：mm → WPF 单位（96/25.4），按 1/2/4 张计算单元格，等比缩放居中，绘制裁剪线。
- `BuildFixedDocument`：每页用 `RenderTargetBitmap` 按输出 DPI 光栅化后再放入 `FixedPage`。这一步是为修复「多页打印出来都是最后一张」的 bug——`DrawingImage` 是懒求值对象，XPS 序列化时才统一求值，会复用最后一次绘图状态。
- `PrintPages`：`CreateXpsDocumentWriter` 提交，任务描述带 GUID 前缀便于识别；随后轮询队列 60 秒判断完成/异常。
- DPI 映射：草稿 150、标准 300、高画质 600。

### 6.10 基础设施

- `ExportService`：SQL/CSV/JSON 均写 UTF-8 **带 BOM**（便于 Excel 正确识别中文）。
- `ImportSettingsService`：配置写在**程序目录** `settings.json`；读取失败静默回退默认值，保存时归一化（数据库名、表名、批量行数、导出路径、快速建表前缀）并触发 `SettingsSaved`。
- `ToastService`：基于 `Adorner`，同一容器复用同一个 Adorner，1.5 秒后自动移除，不拦截鼠标。
- `AppMessageBox`：确保在 UI 线程弹窗（非 UI 线程用 `Dispatcher.Invoke`），并自动挑选当前活动窗口作为 Owner。

## 12. 已知限制与维护提示

### 12.1 功能边界

1. **不直连数据库**：SQL 生成与校验都基于文本，不执行、不校验外键存在性。
2. **校验只支持 SQL Server / PostgreSQL**：`DvDbType` 仅两个枚举值；MySQL / Oracle 只能生成 SQL，不能做数据校验。
3. **OFD 未实现渲染**：可选择、可登记，但预览与打印为空。
4. **画板依赖外网与 WebView2 Runtime**：导出 PNG/SVG 是通过注入 JS 尽力而为，Excalidraw 前端结构变化会导致失效。
5. **临时建表全部输出字符串类型**：不会自动生成日期/数值列；需要精确类型请走「快速建数据表」或手工调整。
6. **CSV 对比状态只在内存**：重启程序后不保留。
7. **校验不覆盖业务语义**：不校验跨字段关系、日期合理区间、JSON Schema。

### 12.2 代码层面值得注意的点

| 问题 | 说明 |
|------|------|
| 版本号三处不一致 | `WpfApp1.csproj` 为 `2.0.0`，首页徽标写死 `v2.3.5`，`页面功能映射.md` 写 `v2.3.3`。发布前应统一，建议首页改为读取程序集版本 |
| `InvoicePrintService.cs` 注释乱码 | 大量注释呈 `鈺愨晲...` 形态，是 UTF-8 文件被按 GBK 读写后的残留；不影响编译，但影响可读性 |
| 死代码 | `SqlGeneratorService.InferColumnKind`、`CsvComparePage.TryAutoCompare`、`JsonToolService.ParseToTree/ExtractByPath`、`DatabaseImportService` 均无调用 |
| 未使用的包 | `Microsoft.Data.SqlClient`、`Npgsql` 仅声明未使用 |
| UI 层过重 | `JsonToolPage.xaml.cs` 3,175 行、`DataValidationPage.xaml.cs` 2,269 行，界面与业务逻辑高度耦合，改动风险集中 |
| 静态可变状态 | `CsvCompareStateService.State` 是全局单例，多窗口/多实例场景下会互相覆盖 |
| 硬编码颜色 | 页面内大量 `Color.FromRgb(...)`，主题切换无法覆盖 |
| 版本元数据 | `ReleaseDate` 在编译时写入（`$([System.DateTime]::Now...)`），非确定性构建；`HomePage` 用 `.Single()` 读取，元数据缺失会抛异常 |
| 剪贴板 | 大文本复制走 Win32 API，失败后回退 WPF 剪贴板重试 5 次；极端占用时仍可能失败并提示 |

### 12.3 建议的改进顺序

1. 统一版本号来源（csproj → 程序集 → 首页显示）。
2. 修复 `InvoicePrintService` 注释编码，避免后续维护误读。
3. 把 `JsonToolPage` / `DataValidationPage` 的状态机与渲染逻辑抽成独立类，降低单文件体积。
4. 将 `tests/DataImportPerformance` 纳入解决方案，并补充解析/生成/校验的纯逻辑单元测试（这些服务都是静态方法，易于测试）。
5. 清理未使用的包与死代码，减小发布体积。
6. 若需要写保护目录运行，把 `settings.json` 迁到 `%LOCALAPPDATA%\CCToolbox`。

## 13. 扩展指引

### 13.1 新增一种数据库（以 SQLite 为例）

1. `SqlGeneratorService.DbType` 增加枚举值。
2. 在 `GetDefaultTableName`、`NormalizeTableName`、`WrapName`、`GetCreateTablePrefix/Suffix`、`GetSqlType`、`GetPreviewSuffix`、DROP 分支中补齐该库语法。
3. `QuickTableService.MapType` / `QuoteName` 增加映射。
4. `ImportSettingsService.NormalizeDbType` 与设置页下拉加入选项。
5. 若要支持校验，还需扩展 `DvDbType` 与 `SchemaNormalizer`。

### 13.2 新增一种校验类型

1. `DvNormalizedType` 增加枚举。
2. `SchemaNormalizer` 把数据库原生类型映射到新枚举。
3. `ValidationEngine.ValidateCell` 的 `switch` 增加分支，并实现对应 `ValidateXxx`。
4. `DdlParser` 若涉及多词类型，补 `NormalizeRawType`。
5. `docs/data-validation-rules.md` 同步更新。

### 13.3 新增一个页面

1. `Views/` 下新建 `Page`（xaml + code-behind）。
2. 需要业务逻辑时在 `Services/` 增加静态服务，避免把算法写进 code-behind。
3. `MainWindow.xaml` 增加 `RadioButton`（`NavButtonStyle`、`GroupName="Nav"`）。
4. `MainWindow.NavButton_Checked` 增加导航分支。
5. 若需首页入口，在 `HomePage.xaml` 加卡片并在 code-behind 写跳转。
