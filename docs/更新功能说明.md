## 4. 清单契约

托管路径：`https://chenmo02.github.io/CCToolbox/updates/stable/latest.json`（仓库 `updates/stable/latest.json`，Pages 从 `main / (root)` 部署，`.nojekyll` 保留）。

同一份文件也可从 `https://raw.githubusercontent.com/chenmo02/CCToolbox/main/updates/stable/latest.json` 读取。主源最多等待 4 秒，不可达（503 / 超时 / DNS 失败）时客户端自动回退到该备用源并在日志中记录；因此**清单文件必须 commit + push 到 `main` 后在线上才存在**，未推送时两个源都会返回 404 或 503。

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema` | int | 固定 `1`，其他值直接拒绝 |
| `product` | string | 必须等于 `CCToolbox` |
| `channel` | string | `stable`；第 1 期只发布一份 stable 清单，设置页不列出不可选的 `beta` 占位项 |
| `version` | string | 三段版本号，与 csproj `<Version>` 一致 |
| `releaseDate` | string | `yyyy-MM-dd`，晚于当前日期一天以上视为异常清单 |
| `minimumVersion` | string | 低于此版本时按强制更新处理（隐藏「跳过此版本」） |
| `mandatory` | bool | 强制更新标记 |
| `downloadUrl` | string | 下载页；仅允许 HTTPS 且主机为 `github.com` / `*.github.com` / `github.io` / `*.github.io`，否则回退到官方 Releases 页 |
| `releaseNotesUrl` | string | Release 说明页（预留） |
| `changelog` | string[] | 更新窗口展示的条目 |
| `package` | object | 第 2 期预留：`url` / `rid` 已写入，`size` / `sha256` 在启用自动下载前补齐并强制校验 |

客户端校验规则：`schema` 与 `product` 匹配、版本号可解析且为三段、**只升不降**、发布日期不是未来时间、下载域白名单；任一不通过即忽略本次结果并写日志。

## 5. 发布流程

**推荐：一键打包**（双击 `scripts\一键打包.bat` 后输入版本号，或使用命令行）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/Build-Release.ps1 -Version 2.3.9
powershell -ExecutionPolicy Bypass -File scripts/Build-Release.ps1 -Version 2.3.9 -DryRun   # 演练
```

脚本依次完成：同步 csproj 四处版本号 → `dotnet publish`（单节点编译，规避 BG1002）→ 校验 exe 的 `FileVersion` → 计算大小 / SHA256 并重新生成 `latest.json` → 同步官网下载区快照 → 在 `artifacts/releases/` 归档 `CCToolbox-vX.Y.Z.exe` 与 `.sha256`。任一步失败会还原 csproj 的原始版本号。

**发版仍需人工完成**：检查改动并提交 → `git tag vX.Y.Z` 并 push → 上传归档 exe 到 GitHub Releases（附件名保持 `CCToolbox.exe`）→ 验证 Pages 与 raw 两个清单 URL 都返回新版本。脚本不会自动 commit / tag / push、上传 Releases 或做代码签名。

`-ExecutionPolicy Bypass` 只对本次进程生效：本机默认策略禁止运行未签名的 `.ps1` 脚本。两个 `.ps1` 均保存为 **UTF-8 BOM**，避免 Windows PowerShell 5.1 把中文按 ANSI 解码；`latest.json` 则写为**无 BOM 的 UTF-8**，避免 HTTP 客户端解析失败。

`scripts/publish-update-manifest.ps1` 由打包脚本自动调用，也可单独使用：`-Mandatory`、`-MinimumVersion`、`-ExePath`（写入 `size` / `sha256`）、`-Changelog`。完整参数与备查命令见 `publish/打包命令.txt`。

## 6. 配置与日志

| 路径 | 内容 |
|---|---|
| `%LOCALAPPDATA%\CCToolbox\update-settings.json` | 自动检查开关、通道、更新源地址、跳过的版本、上次检查时间 |
| `%LOCALAPPDATA%\CCToolbox\logs\update.log` | 检查结果与失败原因；超过 512 KB 时保留最近 2000 行 |

设置入口：**系统参数配置 → 软件更新**，检查入口、检查结果与上次检查时间都集中在该卡片；首页只显示版本号，不展示检查按钮或角标。更新源可填写 HTTPS 地址、本地路径或 UNC 共享路径（例如 `\\server\share\updates\latest.json`）；「选择本地清单」用文件对话框选中 `latest.json` 后自动填入路径（需再点「保存更新设置」），适用于本机调试、内网或公网不可达；「打开配置目录」可直达上述目录。配置写在用户目录，避免了程序放在只读位置时保存失败的问题。

检查失败时按原因分别提示：404（清单尚未发布）、503 / 5xx（服务端或网络代理问题）、连接超时、DNS 失败、清单格式错误，并在弹窗中给出对应处置建议，不再笼统显示「无法连接更新源」。

UI 约定：自动检查用滑动开关（不使用对勾复选框）；下拉框沿用 `SqlPreferenceComboBox` 且必须带 `ItemContainerStyle="{DynamicResource ComboBoxItemStandard}"`，与「默认数据库类型」保持一致。

## 7. 隐私与网络

- 自动检查只发出一次 `GET latest.json`（附加时间戳参数防缓存），`User-Agent` 为 `CCToolbox/<当前版本>`；**不上传任何文件、业务数据或机器标识**。
- 自动检查可在设置页关闭；关闭后只有手动点击「检查更新」才会联网。
- 手动点击「前往下载」使用系统默认浏览器打开 GitHub Releases 页面，程序本身不下载文件。
- 核心表格 / JSON / 校验 / 发票处理仍全部在本机完成，README 与官网中「不上传文件」的承诺不变。
